# ReaTerm v0.1 threat model

## Intended security property

The ReaTerm process implements a fixed subset of native file-inspection
operations and cannot intentionally mutate files or execute other programs.
On Linux x86-64 and ARM64, mandatory Landlock ABI v3+ and seccomp
restrictions protect files from writes and metadata mutation. On macOS
Intel and Apple Silicon, a mandatory Seatbelt sandbox denies filesystem
writes and process/network operations. On Windows x86-64, the native
command thread uses a low-integrity write-restricted access token. cap-std constrains native file
paths to a caller-selected root on both systems.

## Attacker-controlled input

- command names, argument strings, flags and filesystem operands
- filenames, file contents, symlink targets and directory structure
- filesystem changes performed concurrently by other processes
- responses from an optional decision model (which can only veto)
- OpenAI/Anthropic tool arguments generated by external models (untrusted)

## Trusted components

- the compiled Rust program and its trusted dependencies
- a Linux kernel with Landlock + seccomp, a macOS kernel accepting
  Seatbelt, or a Windows kernel supporting write-restricted tokens
- a trusted launcher choosing the root and inherited file descriptors
- the administrator deciding whether an external decision model is allowed

## Enforced rules

- No dynamic shell or arbitrary external executable invocation.
- Python function-tool schemas do not grant native capabilities. The executor
  checks command/args shape and native read-only names, never accepts root or
  executable selection from model input, and delegates to Rust for enforcement.
- Unknown commands and flags are rejected, not silently forwarded.
- Operand paths are relative and capability-scoped. Parent traversal and
  absolute paths are forbidden.
- Content commands reject symlink operands and special files.
- File reads, output length and directory listing counts are bounded.
- Linux Landlock + seccomp, macOS Seatbelt, or Windows write-restricted
  thread impersonation is installed before dispatch. The Windows token
  is installed before opening any capability root directory handle.
  Any setup failure is fatal with no unconfined fallback.

## Non-goals and residual risk

- **Parent-shell operations:** the host shell processes >, >>, pipes and
  substitutions outside ReaTerm. Its redirection can truncate a file even
  when ReaTerm itself performs no filesystem write.
- **Confidentiality:** callers choose --root and may read secrets within it.
  The tool is not an authentication or data-loss-prevention system. Returning
  file contents or stdout to an external model provider may disclose sensitive
  information inside the caller-selected root; limit roots accordingly.
- **Already-open descriptors:** Landlock does not revoke rights on open fds.
  Do not launch from an untrusted process with writable inherited fds.
- **Networking/IPC:** no network/IPC interface is exposed in the native
  command set. This is not an arbitrary-code execution sandbox.
- **Other processes:** restrictions do not apply to siblings or parent shell.
- **Platforms:** Linux x86-64/ARM64, macOS Intel/Apple Silicon and
  Windows x86-64. Windows ARM64 and 32-bit ARM are not verified. Apple's sandbox_init API is
  deprecated and could stop working; this must fail closed.
- **Kernel vulnerabilities:** no OS sandbox can rule out kernel bugs or
  unusual side effects of hostile filesystems.

## Review checklist

Every new command must document path handling, flags, environment variables,
hooks, subprocesses, resource usage and side effects. Prefer native read-only
implementations. Add adversarial tests before relaxing any restriction.


## Metadata mutation gap and defense

The Linux Landlock filesystem access-rights API (including ABI v3) does
not cover chmod, chown, file extended-attribute modifications or timestamp
mutations. ReaTerm therefore requires a second filter: a Linux seccomp-BPF
syscall policy that returns EPERM for known metadata mutation syscalls and
mount-related operations. This is enforced after Landlock and before
command dispatch; any installation failure aborts. The current seccomp
policy supports only native Linux x86-64 and ARM64 syscalls; other
architectures fail closed. The command dispatcher itself never exposes
chmod/chown or arbitrary external executables.

This defense does not provide authorization over the parent shell, siblings,
or previously opened descriptors. ReaTerm cannot prevent a caller from
writing redirected stdout to a file outside its process.

 
## macOS Seatbelt enforcement

On macOS Intel and Apple Silicon, the Rust process installs a Seatbelt
profile with `sandbox_init` after opening the capability root but before
native dispatch. It starts with an allow baseline for regular process
operations and explicitly denies `file-write*`, `file-link`,
`process-exec`, `process-fork`, and `network*`, without write
exceptions. The file-write category includes chmod/chown, xattrs,
timestamps, file creation, deletion and renames. If Seatbelt cannot be
applied, ReaTerm aborts the command.

Apple **deprecates** sandbox_init. Future OS versions can restrict it.
The tests spawn a dedicated child to install Seatbelt and attempt
chmod/chown, file creation/removal, plus a permitted read. The sandbox
is an additional defense; neither the parent shell nor inherited writable
file descriptors are constrained by applying Seatbelt to ReaTerm itself.


## Windows write-restricted token

On Windows x86-64, the native Rust CLI uses Win32 CreateRestrictedToken
with WRITE_RESTRICTED and DISABLE_MAX_PRIVILEGE, a low mandatory
integrity label, and a newly generated
cryptographically random restricting SID, and a mandatory
ImpersonateLoggedOnUser call before opening the capability root. File
reads use the normal user's permissions; writes against ordinary DACL-
protected objects need permission from both the normal identity and
the random restricting SID, and are therefore denied. Low mandatory
integrity also denies deletes and other write-up operations against
ordinary medium/high integrity files. Any failure
to initialize the token rejects the command rather than continuing
unrestricted.

**This is a thread-local guard, not a process-wide OS sandbox.** It does
not restrict a separate thread, a child process, a previously opened
writable handle, or objects with permissive null DACLs, or low-integrity objects
where the access controls grant deletions. The Rust
dispatcher does not create worker threads or subprocesses, and unknown
commands cannot be executed. A trusted launcher is still required.
The parent PowerShell/cmd shell may write redirected output independently.
Tests on Windows attempt direct file writes, creation, rename, deletion,
and file-attribute changes on disposable fixtures. They do not constitute
a general sandbox or malware-containment guarantee.
